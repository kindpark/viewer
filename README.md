# Sekai.best 사이트 크롤링을 통한 랭킹 사이트 만들기

개발 배경

내가 하는 게임의 실시간 랭킹 정보를 제공해주는 사이트를 3학년 여름방학때 개인 NAS를 이용해서 개인적으로 만들어봤으나, 이용자가 20명 가까이 됐었다보니 서버 부하, 사진 이미지를 제대로 불러올수 없어서 단일 사진만을 사용했었다는 문제가 있었고, github코드도 내렸던 경험이 있다.

이번에는 이를 보완하고자 하나 만들어봤다.

구조도

sekai-master-db-diff와 api.sekai.best에서 데이터를 가져온다.

서버가 시작될때, 매일 새벽 4시에 마스터 데이터를 동기화하고 10분마다 랭킹을 수집하여 DB에 저장한다.

DB는 

- `event`: 이벤트 번호, 이름, 기간
- `card_master`: 카드 이미지 CDN URL, 속성, 레어리티
- `snapshot`(`event_ranking_snapshot`): 수집 시각별 순위, 점수, 그 시점의 리더 카드 ID와 각성 여부
- `player`: 유저 원본 JSON (지금은 디버깅용 성격)

가 있다.

서비스와 컨트롤러 부분의 스냅샷, 카드 ID로 card_master를 조회하여 이미지 URL을 받아온다.

프론트엔드 측에서 해당 데이터를 받아 랭킹 차트, 리더보드를 채운다.

물론 프로그램의 데이터 호출이 늘 사진과 같은것은 아니다. 단순 조회할때를 예로 들면 서비스가 DB를 조회하고 브라우저가 서비스를 호출하는식이다. 이럴때는 서비스는 양방향에서 역할을 한다고 생각한다.

데이터 흐름은 두 가지다.

- 수집: 스케줄러가 외부 API에서 받은 데이터를 DB에 저장한다.
- 조회: 브라우저가 컨트롤러를 호출하면 서비스가 스냅샷을 조회하고, 카드 ID로 card_master를 찾아 이미지 URL을 붙여 응답한다. 프론트엔드는 이 데이터로 리더보드와 커트라인 차트를 그린다.

이걸 개발하면서 얻어낸 성과는 다음 두가지이다.

- 외부 API 호출은 이용자 수와 상관없이 서버가 10분마다 한 번만 합니다. 접속자가 늘어도 sekai.best에 가는 요청은 늘지 않습니다.
- 카드 이미지는 서버가 아니라 CDN에서 바로 받으므로 서버가 이미지를 전송하지 않습니다.
